Автор big_energy. Версия сборки 2.0.3, Minecraft 1.20.1, Forge 47.4.10 и Java 17. Официальный клиент CurseForge `1771794/9558909` весит 2 214 600 байт. SHA‑256 `23e5968067ad91b55e60bbd85ecd0de3b5a8a46cf7d06f6684c8d565f0d62580`. В исходный lock входят 161 обязательная зависимость и 1011 файлов авторского слоя. [Выпуск 2.0.3](https://www.curseforge.com/minecraft/modpacks/antimatter-chemistry-reforged/files/9558909)

Сборка занимает ID `minecraft-17` и использует собственную папку `Antimatter Chemistry Reforged`. В каталоге следует изменить только строку `minecraft-17`, без алиасов старой папки или источника. Миры Antimatter Chemistry 1.4.10 остаются по своему пути.

## Подготовка и приёмка

Укажите путь к официальному ZIP через `$authorZip`. `$stage` должен быть новой папкой внутри своего `artifacts/agent-runs/<task-id>` с `RUN.json`. Из корня исходников LANMinecraft выполните стандартную подготовку CurseForge из [инструкции](https://github.com/MarkZamore/LANMinecraft/blob/main/tools/PackData/CurseForge/README.md). `tools/upstream-client-lock.json` закрепляет входные файлы. `tools/overlay.json` связывает их со слоем журнала и параметром сохранения настроек мира при открытии сети.

Тот же рецепт добавляет в стартовый скрипт KubeJS вызов штатного переключателя Supplementaries, который отключает уведомление об Amendments до первого главного меню. При обновлении автора сохраняйте эту правку через `release_overlay.py review-update`. Если автор изменил исходный скрипт, перенесите обработчик и пересчитайте хеши в рецепте и полном lock. Перед выпуском проверьте чистый запуск и запуск с `general.no_amendments_screen = false` в существующем клиентском конфиге.

При старте клиента тот же скрипт устанавливает штатный флаг Minecraft 1.20.1 `skipMultiplayerWarning`. Он отвечает только за экран о сторонних серверах перед списком серверов. Скрипт устанавливает значение в памяти независимо от наличия или содержимого авторского и личного `options.txt`. Рецепт переносит обработчик при обновлении. Если автор изменил сам скрипт, `review-update` остановится для переноса правки. Проверка `stage_multiplayer_warning.py --verify <папка игры>` обязательна в подготовке выпуска и проверяет фактически подготовленный скрипт. Для выпуска одной этой правки параметр `warning_base` задания `publish.yml` принимает SHA-256 текущего манифеста `pack-latest`.

## Книга заданий FTB Quests

Язык заданий следует выбору языка Minecraft. FTB Quests 2001.4.22 читает текст из полей SNBT. Слой `bookLocalization` подставляет в эти поля языковые ключи, а KubeJS загружает английский оригинал и русский перевод из `kubejs/assets/reforged_quests/lang`. Идентификаторы заданий, условия, награды и структура глав сохраняются.

При обновлении автора сначала выполните `release_overlay.py review-update` для нового клиентского lock. Если автор изменил квестбук, выполните из корня репозитория сборки:

```powershell
python -B tools/localize_quests.py reuse $authorZip $translationTables
```

Укажите новый каталог для `$translationTables`. Команда выносит прежние переводы совпадающих строк в таблицы по главам. Файлы `*.missing.json` содержат новые и изменённые строки. Добавьте их ручной перевод в соответствующие таблицы. После проверки нового рецепта и полного авторского lock примените слой:

```powershell
python -B tools/localize_quests.py build $authorZip $translationTables
python -B tools/localize_quests.py verify $authorZip
```

Проверка читает весь квестбук из авторского архива, поэтому также обнаруживает новые главы. Перед публикацией повторите нативную проверку на текущем Forge. В уже открытом мире переключите язык с английского на русский и проверьте название главы, название и описание задания и кликабельную ссылку. Тестовый агент находится в `tools/native/ReforgedQuestLocaleQa.java`.

На точном Forge 47.4.10 проверьте создание мира через `minecraft:normal`, появление на равнине антиматерии и выдачу стартового набора в инвентарь через `amworld:first_join`. После повторного входа проверьте квесты и отсутствие повторной выдачи набора. Отдельно проверьте скины, локальное подключение хоста и гостя, сообщения после открытия мира, пропуск промежуточного окна, кнопку «Жалобы», сохранение режима и выполнение `/time` гостем при разрешённых командах. Для тестов нужен отдельный экземпляр со своим миром.
